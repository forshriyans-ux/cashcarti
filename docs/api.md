# Backend API

`docs/openapi.json` is generated by `npm run api:generate`. Runtime validation uses the same project/report/source/requirement Zod schemas. `src/api-types.ts` exports TypeScript response types; `src/client.ts` wraps core frontend calls.

All routes except health require `Authorization: Bearer <token>` and `X-Organization-Id: <uuid>`. Selected membership and tenant ownership are enforced; inaccessible resources return 404. Unknown properties in request bodies are rejected. Collection routes accept `limit` (1–100, default 25) and `offset` (0–100000, default 0); collection responses contain `{data,limit,offset}`. Resource UUIDs and query parameters are runtime-validated.

Errors use `{error:{code,message,requestId,fields?}}`. Important errors: `NO_VERIFIED_RULESET` (409), `REPORT_NOT_READY` (409), `PROCESSING_ACTIVE` (409), `FILE_TYPE` (415), `FILE_REJECTED`/`PAGE_LIMIT` (422), `FILE_SIZE` (413), `AI_BUDGET` (429), `NOT_PROVISIONED` (403), `NOT_FOUND` (404). Responses include server-generated `X-Request-Id`; synthetic mode includes `X-PermitProof-Mode: synthetic-demo`. Rate limiting also uses 429.

| ------------------ | ------------------------------------------- | --------------------------------------------------------------- |
| GET                | `/api/health`                               | Anonymous readiness/mode and capability flags                   |

| GET, PATCH, DELETE | `/api/projects/:id`                         | Read/update or queue private deletion (202)                     |
| POST, GET          | `/api/projects/:id/documents`               | Upload (202, duplicate 200) or list                             |
| GET, DELETE        | `/api/documents/:id`                        | Metadata/page-status collection or queue deletion (202)         |

Project creation body:

```json
{
  "name": "My ADU project",
  "projectType": "new_adu",
  "jurisdictionId": "<jurisdiction UUID>",
  "permitProfileId": "<profile UUID>",
  "address": "Optional user-entered address",
  "filingDate": "2026-10-01"
}
```

PATCH accepts only `name`, `address`, and `filingDate`. Server tenancy, jurisdiction, and profile cannot be reassigned through PATCH. Upload uses `multipart/form-data` with exactly one binary `file` part; repeat requests for multiple files. Review POST has no body: it pins the saved project and current uploaded documents. Poll `GET /api/reviews/:id` every 1–2 seconds, stop on completed/failed, and fetch findings/report only after completed. Failed runs and unreadable pages remain explicit.

Global government-rule administrator routes (all authenticated and audited):

| Method    | Path                                 | Action                                                                           |
| --------- | ------------------------------------ | -------------------------------------------------------------------------------- |
| GET       | `/api/admin/sources`                 | Saved source versions and verification states                                    |
| POST      | `/api/admin/sources/retrieve`        | `{url,jurisdictionId,agency}`; bounded government HTML fetch, no activation      |
| POST      | `/api/admin/sources/import`          | Exact manual text, official URL, metadata, and literal source-import attestation |
| POST      | `/api/admin/sources/:id/verify`      | Literal verification attestation                                                 |
| GET, POST | `/api/admin/requirements`            | List or draft structured requirements with exact source excerpt                  |
| POST      | `/api/admin/requirements/:id/verify` | Literal requirement-verification attestation                                     |
| POST      | `/api/admin/rulesets`                | Publish `{profileId,version,requirementIds,effectiveFrom,effectiveTo?}`          |

Exact attestations and field schemas are in OpenAPI. They record an accountable human action; they are not substitutes for that review. No model-generated rule is automatically activated. Effective intervals are inclusive filing dates. Only approved government domains over HTTPS are accepted; automated redirects and uncontrolled crawling are disabled. PDF text can be imported manually after authorized retrieval and human verification.
